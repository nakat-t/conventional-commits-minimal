# commit-msg hook

Two equivalent implementations of a Git `commit-msg` hook that rejects commit
messages which do not follow
[Conventional Commits Minimal](../README.md):

| File             | Runtime                                                  |
|------------------|----------------------------------------------------------|
| `commit-msg.sh`  | POSIX `sh` (dash, bash, zsh in sh mode, Git for Windows) |
| `commit-msg.ps1` | Windows PowerShell 5.1 or PowerShell 7+                  |

Neither script needs anything beyond what ships with Git or the operating
system. Pick whichever fits your team; behavior is identical.

## What is checked

* The first non-comment line matches `<type>[!]: <description>` where `type`
  is exactly `feat`, `fix`, or `chore`.
* No scope (`feat(api):` is rejected).
* If a body or footers follow, the second line is blank.
* A `BREAKING CHANGE:` / `BREAKING-CHANGE:` footer is uppercase and only
  appears when the header contains `!`.
* Comment lines (`#`) and everything after a scissors line
  (`git commit --verbose`) are ignored.

Messages generated by Git itself are skipped without inspection:
`Merge ...`, `Revert "..."`, `fixup! ...`, `squash! ...`, `amend! ...`.

## Install

### Option A: copy into `.git/hooks` (per clone)

Git runs the executable named `commit-msg`; the extension must be dropped.

macOS / Linux / Git Bash:

```sh
cp hooks/commit-msg.sh .git/hooks/commit-msg
chmod +x .git/hooks/commit-msg
```

Windows, PowerShell implementation — Git cannot execute a `.ps1` directly, so
`.git/hooks/commit-msg` must be a small `sh` wrapper (Git for Windows always
provides `sh`):

```sh
#!/bin/sh
exec powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(dirname "$0")/commit-msg.ps1" "$1"
```

Then copy `hooks/commit-msg.ps1` next to it. Replace `powershell.exe` with
`pwsh` if you prefer PowerShell 7.

### Option B: track the hooks in the repository (shared)

Commit the `hooks/` directory to your project, rename `commit-msg.sh` to
`commit-msg` (or add the wrapper above), and have every contributor run once:

```sh
git config core.hooksPath hooks
```

## Use outside Git (CI, editors, agents)

Both scripts accept the message on standard input when no file argument is
given, and exit with status `1` on a violation:

```sh
printf 'feat: add export command\n' | sh hooks/commit-msg.sh
git log -1 --format=%B | sh hooks/commit-msg.sh
```

```powershell
'feat: add export command' | pwsh -File hooks/commit-msg.ps1
git log -1 --format=%B | pwsh -File hooks/commit-msg.ps1
```

## Tests

```sh
sh tests/run.sh                 # or: SHELL_CMD=dash sh tests/run.sh
pwsh -File tests/run.ps1        # or: powershell -File tests/run.ps1
```

Each fixture under `tests/fixtures/{valid,invalid,skip}` is fed to the hook
both as a file argument and via stdin.
